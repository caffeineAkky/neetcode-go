# 242. valid-anagram (Easy)

- 問題: https://leetcode.com/problems/valid-anagram/
- NeetCode: https://neetcode.io/problems/valid-anagram
- カテゴリ: arrays-hashing

## 解法を一言で
まずは、与えられた2つの配列の長さが異なる場合、アナグラムではないためfalseを返却する。
次に、英字26文字の配列を作り、与えられた2つの配列の文字に対応するインデックス値を+-していく。
最終結果が26の0値配列であれば、アナグラムと判定できる。

## 計算量

- 時間: O(n)
- 空間: O(1)

## 詰まった点・覚えること
### 配列の作成方法
``` go
var a [5]int   // [0,0,0,0,0]と、ゼロ地初期化された固定長の配列が作成できる
b := [3]string{"a", "b", "c"}
c := [...]int{1, 2. 3}.    // 長さは要素数から決まる(3)
d := [5]int{1: 10, 3: 30}  // インデックスを指定 → [0, 10, 0, 30, 0]
```

### mapか配列か
mapと配列だと、配列の方が高速。
なぜなら、配列はメモリに等間隔に要素が並んでいるが、mapだと要素が追加される度にメモリを確保しにいく必要が亜ある。また、配列だとハッシュ計算する必要もないため。

### {}ありなしの差 = 型と値の違い
``` go
[26]int   // 型で、intが26個並んだ配列、という意味。
[26]int{} // 値で、その型の、全部0の配列そのもの
```

### ''と""の違い
``` go
'a' // 文字コードを表す。値は97。英子文字はASCIIコードで連番。
"a" // aという文字列。
```
s[i]は、返却値は文字列ではなくbyte。
たとえば、s[i] = "c"だったら、返却値は99ということになる。

なぜか？
→Goの文字列の中身は、数字の列だから。
"hello" は、コンピュータの中ではこう保存されている
```
文字: h   e   l   l   o
中身: 104 101 108 108 111
```
